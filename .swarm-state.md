## #402 provenance — Phase 2 (glue/binary pair assertion at boot) — 2026-09-09 — complete

### Design note — why byte length, not a self-reported stamp
`WASM_ARTIFACT_STAMP` is a sha256 **over** the built glue + binary, so the module
cannot carry it: baking the stamp in would change the bytes it hashes. The assert
therefore compares the **served byte lengths** of both passengers against the sizes
recorded in the build identity (Phase 1) — the fallback named in the brief, and the only
non-circular option short of a second hash artifact. No C++ change was needed, so
`getVersion()` stays 8.

### Files
| File | Change | Why |
|------|--------|-----|
| `src/systems/water/WatershedWasm.ts` | `WasmProvenanceMismatchError`, `describeProvenanceMismatch()`, `buildArtifactProbes()`, `fetchArtifactByteLength()`, `probeArtifactProvenance()`, `__setBuildIdentityForTests()`; probe starts beside the factory and is consulted on **both** the success and the throw path | Assert the pair in one page load without adding boot latency |
| `src/physics/workerWasm.ts` | Same assert, honoring the resolve-null contract; distinct `provenance-mismatch(...)` log | Physics worker falls back to TS math, but says why |

### Cause beats symptom (design change found by the proof, not by reasoning)
The first live proof showed a mismatched pair throws **inside** the Emscripten factory —
`TypeError: wasmTable.get is not a function` — *before* a post-init check can run, so the
banner said "failed to init" and the real cause was invisible. The probe is now started
before the `try` and consulted in the `catch`: when a mismatch is pending, it replaces the
generic error and the underlying throw is appended in parentheses.

### Bug found by pointing the tool at the real server
`node`'s `fetch` sends `accept-encoding: gzip`; the deploy target gzips `.js`/`.wasm`, so
`content-length` came back **16146** for a **33817 B** wasm. Left unfixed, both the verifier
and the browser-side guard would have cried mismatch on a perfectly healthy deploy — a
false positive is how a guard gets switched off. Both now trust `content-length` only on an
identity-encoded response and otherwise measure the decoded body. Covered by tests on both
sides.
