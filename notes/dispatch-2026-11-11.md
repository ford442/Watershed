```markdown

## Context (verified on `main` 2026-11-11)
- No i18n layer: no `src/i18n/`, no `t()`, no catalog anywhere in `src/`.
- Literal English in JSX. Rough count of JSX-text lines (grep, not exact): `StartMenu.tsx` 19, `ui/SettingsPanel.tsx` 12,
  `GameHUD.tsx` 8, `PauseMenu.tsx` 4, `GraphicsUnsupported.tsx` 4, plus `RunResultsPanel.tsx`, `ExperienceUI.tsx`,
  and `aria-label` / `title` attributes throughout.
- Strings built outside JSX: `systems/water/hydroHud.ts` (the HUD subtitle is "one clause"), and the map menu
  labels in `src/maps/registry.ts` (`label: 'Glacial Source'`, `'Lumber Flume'`, `'Meander to Waterfall'`,
  `'Hydro-Dam'`, `'River Delta'`).
- Numbers already go through `toLocaleString()` (`GameHUD.tsx`, `StartMenu.tsx`). Durations, splits and plurals are
  concatenated by hand.
- Settings persist through `useSettingsStore` (`SETTINGS_VERSION = 2`). A locale setting means a v3 migration.
- Lint gate is `--max-warnings 0` once PR #560 (#554 E) is on `main`.

## Proposed approach (first pass)
1. `src/i18n/en.ts`: a nested `as const` catalog, the key source. `MessageKey` is the union of its dotted paths.
   `t(key, params?)` does `{name}` interpolation. Plurals pick `key.one` / `key.other` (and the CLDR categories a locale
   needs) via a cached `Intl.PluralRules`. `useT()` re-renders on locale change. `src/i18n/format.ts`:
   `formatNumber`, `formatDuration`, `formatSplit` (±m:ss.t) over cached `Intl.NumberFormat` /
   `Intl.RelativeTimeFormat` instances per locale. Do not allocate per frame on HUD paths (see
   docs/reference/ALLOCATION_BASELINE.md). Do not use `Intl.DurationFormat`: it is above the Chrome 94 / es2022 floor.
2. Locale: `'system' | 'en' | 'es' | 'fr'` in the settings store (v3 migration, default `'system'` → first match in
   `navigator.languages`, else `en`). Options → General gets a picker. `<html lang>` follows the resolved locale.
3. `es` and `fr` load as lazy chunks (`import()` of JSON or TS). English renders while they load, and a missing key
   falls back to English (dev: one `console.warn` per key). They must not appear in the entry chunk
   (`scripts/check-build-manifest.mjs`).
4. Move every user-visible literal in `src/components` (menus, HUD, results, pause, graphics-unsupported,
   ExperienceUI), `src/ui`, `hydroHud.ts` and the map labels behind keys. Registry rows keep their ids; `label`
   becomes a key. hydroHud: one message per clause, not concatenated fragments, so other languages can reorder words.
5. ESLint: `no-restricted-syntax` on `JSXText` matching /[A-Za-z]{2,}/ and on string `Literal` values of `aria-label`,
   `title`, `placeholder`, `alt` under `src/components/**` and `src/ui/**`. Allowlist (developer surfaces, out of
   scope per #558): `DebugPanel`, `AudioDiagnosticsOverlay`, `MovementReadoutPanel`, `SWEBedDebugOverlay`,
   `LevelEditor/**`, `src/harness/**`. Error severity.
6. Tests: `t()` (interpolation, plural per locale, missing-key fallback); a key-parity test that fails on a missing or
   extra key in `es` / `fr`; one render of StartMenu in `fr`; the settings v2 → v3 migration.

## Acceptance (rough — refine during expansion)
- [ ] No user-visible English literal in `src/components` / `src/ui` outside the allowlist; the lint rule enforces it.
- [ ] `en`, `es`, `fr` ship; key parity is tested; `es` / `fr` are lazy (not in the entry chunk).
- [ ] Locale follows `navigator.languages`, can be overridden in Options, and persists (v3 migration tested).
- [ ] Entry growth is under 4 kB and recorded in `build-budget.json` with the reason.
- [ ] `pnpm typecheck`, `typecheck:test`, `lint` (0 warnings), `test`, `test:perf`, `build` all pass; visual smoke
      `00_start_menu` is unchanged in `en`.
- [ ] `test:input-smoke`, `:gamepad` and `test:replay-smoke` are identical to `main` (strings never touch the sim).

## Out of scope
UI scale / rem conversion (B), glyphs / colour-vision / captions (C), assists (D), axe in CI (E), RTL, developer
overlays, the level editor (#557 owns its UI).

## Open questions (owner)
1. Who writes `es` / `fr`? Machine-translated first draft with a `needs-review` marker in the catalog, or English
   placeholders that only exercise the plumbing?
2. Locale in the settings store (v3) or its own persisted key, so a locale change never touches comfort settings?
3. Map display names: keys in `en.ts`, or a `name` per locale in each map JSON (authored content, #557's editor)?
4. Does the level editor count as player-facing once #557 ships it? If so, take it out of the allowlist then.
5. Is `formatSplit` the single owner of split formatting? Today ghost / results / HUD each format their own.
```
